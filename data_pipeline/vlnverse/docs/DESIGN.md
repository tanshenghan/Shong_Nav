# 从官方逐步位姿到平滑运动

本文描述保留官方路线和逐步对应关系的时间重定分支。允许改变中间路径和消除原地转向的
独立实现见 [A* 连续曲线分支](PLANNED_ROUTES.md)，使用新的运动与数据契约。

## 目标与边界

目标机器人允许原地转向。输入是离散采样的机器人体位姿；输出首先是具有明确合成时间轴、
受速度、加速度和 jerk 约束的连续参考运动，再通过场景回放生成可用于训练的观测和监督。
默认按每个原始运动间隔保存少量位姿点。插值不会恢复官方采样点之间“实际发生过的运动”，
因此必须保留派生数据标识，并区分连续运动定义与存下来的采样点。

必须分别验证三件事：空间路径是否可通行、时间曲线是否平滑、机器人和相机能否在仿真中实现。
位置点之间没有障碍，不等于有体积的底盘能够通过；看起来平滑，不等于满足速度和角速度约束。

## 当前实现：保留路线、重新安排时间

当前使用原始位置序列和机器人 yaw。相邻记录构成直行、原地转向或停留。
同向共线且 yaw 不变的直行可以合并；同向连续原地旋转可以合并。
合并后保留源记录映射，起点、终点在数值容差内保持一致。
为容纳 float32 位置的微小误差，共线合并允许不超过 `max_merge_deviation_m`
的源锚点偏差，默认 0.00001 m；不是逐点字节完全相同的回放，也不是跨房间的路径简化。
每段记录 `max_source_anchor_deviation_m`，合并后的整段也重新检查碰撞。
不符合首版运动假设的输入应明确失败，不通过静默删点、改变路线或任意插值修复。

完全重复的位置与 yaw 没有已知物理停留时长；当前合并这类重复状态并保留源进度映射，
不臆造停车秒数。位置相同但 yaw 改变的原地转向仍保留。

每个合并后的运动段以归一化时间 `u=t/T ∈ [0,1]` 使用七次进度曲线：

```text
q(u) = 35 u⁴ − 84 u⁵ + 70 u⁶ − 20 u⁷
q(0) = 0, q(1) = 1
q′(0) = q′(1) = q″(0) = q″(1) = q‴(0) = q‴(1) = 0
```

这八个端点条件确定七次多项式的八个系数；曲线不是从 5 个点拟合或学习出的模型。
平移时 `p(t)=p_start+q(t/T)·(p_end−p_start)`，原地转向时对展开的 yaw 使用同一进度。
段时长 `T` 根据直线距离或转角，以及线性/角运动的速度、加速度、jerk 上限求出。
端点处前三阶导数都为零，因而直行、停车、转向之间平滑衔接。
同一合并段内的源动作接头不重新停车；需要原地转向的路口仍减速停车。
当前没有绕角弧线优化。

## 默认采样：每个原始运动间隔 6 个点

`sample_mode="per_source_step"` 时，`poses_per_step` 默认为 6，可选 5、6、7、8。
点数包括该原始间隔的起点和终点；相邻间隔共享的端点只保存一次。
完全重复的源状态不构成运动间隔，平移或原地旋转都计作运动。
对于 `N` 个这样的间隔，6 点设置得到 `1+5N` 个采样点；一般为 `1+(K−1)N`。

采样遵循已求出的连续曲线：

1. 先合并同向共线直行/同向原地转向，并求这个合并段的 `T`。
2. 算出各源锚点在合并段中的几何进度 `r_i`；直行用线段投影，转向用累计转角比例。
3. 反解单调函数 `q(u_i)=r_i`，获得曲线上经过各源锚点的时间。
4. 每个 `[u_i,u_{i+1}]` 内按等时间间隔取 6 点，再用 `q` 计算位姿和导数。

所以每个源间隔内的时间间隔相等，但不同源间隔的间隔通常不同。
几何进度随 `q` 变化，六点也不必在空间上等距。每个原始锚点都会经过，
共线合并时允许前述浮点误差上限；同向源动作接头不因采样而停车。

保存多少点与整段运动要持续多久独立。把 6 点改为 5 点只减少记录数，
不会缩短 `T` 或自动加速。读取端必须使用 `timestamp_s`，不能将稀疏点号当作恒定控制周期。

显式选择 `sample_mode="uniform_time"` 时，才使用 `sample_hz`，其配置默认值为 30 Hz。
该模式将段时长向上对齐到时间网格后均匀采样，保留之前的 30 Hz 工作方式。
默认每源间隔采样模式不使用 `sample_hz` 分配时长，质量记录中的 `sample_hz` 为 null。
单个间隔或某些对称锚点可能恰好形成全局等间隔输出；
`manifest.sampling.uniform_timestamps` 根据实际时间戳报告这一点，不能据此推断设置了固定频率。

合成采样记录位置、展开的 yaw、速度、加速度、jerk 和角运动导数，
便于数值审计与后续控制。原始时间戳只保留来源意义，不直接当作真实控制周期。
每段 `primitives` 保存 `source_anchor_indices` 和 `source_motion_count`，
结合源位姿、段时长与七次进度定义，可追溯采样并重建连续参考运动。
导数约束检查使用整段曲线的解析峰值，记录在 `quality.continuous_maxima`；
`quality.maxima` 仅是已保存样本处的最大值。稀疏采样不会跳过连续曲线的峰值检查。

## 当前避障：检查整段底盘扫掠区域

占据图必须经过坐标校准，并覆盖机器人高度范围内的障碍物。
底盘使用外接圆半径加安全余量近似。对每段移动，计算完整中心线段到每个闭合占据栅格矩形的
最小欧氏距离；距离小于或等于半径加数值容差即视为碰撞。这等价于检查圆盘沿线段扫过的区域，
包括圆形端帽，不依赖保存的采样点数。同时检查地图边界；未知区域作为障碍。
原地旋转的圆形包络与 yaw 无关，以零长度线段检查其所在圆盘。

这一步对给定方格地图执行精确的欧氏圆扫掠检查，仅在浮点边界增加很小的保守容差；
不再用矩形膨胀额外封死圆形底盘实际可绕过的格点角落。
此前从原生地图到标准方格的保守重采样仍保留，因此此处的“精确”只指圆与这些格子的几何关系。
地图外不可通行，接触障碍或地图边界也拒绝；不能仅因中心线或端点无碰撞就放行。
输出平面检查通过，只能说明轨迹满足**该地图和该圆形包络**；
不能证明地图漏标的桌沿、低矮结构、动态物体或实际机器人高度范围没有碰撞。
非圆底盘可以先取外接圆，后续再实现具有朝向的多边形包络和连续碰撞检查。

地图坐标错误会让所有后续几何检查失效。使用官方场景前需要检查：

- 米制比例、世界坐标轴、原点、栅格行列方向及旋转。
- 障碍/空闲/未知像素的含义，地图生成高度范围。
- 机器人基座、源记录位置、相机位置之间的变换与高度偏移。
- 起终点和若干路径点是否落在正确房间；至少一个靠墙案例是否正确拒绝。

运动模块仍只接受显式标准 NPZ。已新增的 `scene/official_map.py` 为一种经过验证的官方格式
提供转换：`freemap.npy` 第一行给出递减的世界 X，第一列给出递增的世界 Y；
类别 0/1/2 分别对应占据/空闲/未知，并逐像素核对 `occupancy.png` 的 0/255/127。
坐标表头必须与 `occupancy.json` 边界一致，房间世界顶点必须按最近坐标采样对应
`room_in_images.json` 顶点。转换使用真实 X/Y 采样间距，不直接将名义 scale 当作两个轴的分辨率。
目标方格与任一占据/未知原始像素区域重叠时即标记占据，避免重采样创造空闲捷径。

当前真实校准样例为 `kujiale_0018`，核对了 26 个房间顶点，转换为 0.05 m 方格。
它提供的地图高度范围为 0.1–1.0 m，检查结果仍不覆盖更高的悬挑物或完整机器人高度。
`kujiale_0018_2_2` 的 23 个官方位姿转换为 111 点，合成时长 30.078125 秒。
原始候选 `kujiale_0195_4_2` 在当时的保守矩形膨胀检查下因 0.30 m 包络失败而拒绝，
之后按固定随机种子的候选顺序筛选，过程见 [几何报告](../reports/preview_geometry_20260919.json)。
该报告保留历史算法与筛选结果，不替代当前欧氏圆扫掠算法的重新验收。

## 已实现的视觉预览入口

`replay/blender_render.py` 使用独立的 Blender 4.2 CPU 环境预览真实 USD 几何。
首帧试跑发现 Blender 原生 USD 导入器丢失了父级变换，场景范围与原 USD 不符，
因此原生导入完成不能作为正确加载的证据。当前已接入 `usd_scene.py`，
通过 pxr 提取静态网格、精确世界矩阵、UV 和全路径材质绑定；本例世界变换已验证，
23 帧原始与 111 帧平滑序列全部完成，首中尾视图已核对。
扩展场景时仍须核对世界范围和代表性顶点。
场景资产依照官方 `evaluator/utils/common.py` 的优先级使用 `start_result_navigation.usd`。
本例原始 `kujiale_0018.usda` 保留导航版删除的门体，会遮挡首帧视线；导航版首帧的房间布局已核对。
两版必须使用同一个导航场景入口，不能将原始资产渲染与导航资产渲染混合比较。
`usd_materials.py` 将部分 MDL 颜色、漫反射纹理、UV 变换、粗糙度、金属和玻璃近似到预览材质。
它不执行原始 MDL，未覆盖法线、发光、视角相关颜色等完整着色；还使用统一环境光和相机补光，
因此不能宣称恢复官方外观或与 Isaac RTX 等价。

`replay/isaac_render.py` 提供另一个独立相机入口，使用原场景灯光和原生 Isaac 渲染。
该入口已做 CPU 输入校验，但当前没有 GPU 实测结果。
两条路径都只是给定位置的相机渲染，不加载受控机器人、不证明物理可执行性。
相机高度与视角是显式选定的预览配置，不从源位姿中冒充恢复官方传感器外参。

`replay/compare.py` 的默认 `reference_time` 模式将原始位姿放在平滑曲线经过源锚点的合成时刻，
把两组新渲染 PNG 放到同一个时间轴。每张图保持显示到下一个位姿的时间戳；
不做光流或图像插帧，保存位姿数也不等同于视频容器 FPS。
因此两版有相同总时长，原始版表现为源位姿间的跳变，平滑版显示更密集的真实几何视图。
视频结尾会按容器帧周期量化并保留终点，精确参考/视频时长分别写入 comparison manifest。
本例三段视频均完整解码通过，603 帧、20 FPS、30.15 秒；23 个源锚点的两版 RGB 逐像素一致。
证据见 [预览生成报告](../reports/preview_render_20260919.json)，验收范围限于该例 CPU 视觉预览。
另可用 `pose_frames --fps 15` 逐位姿播放：111 个平滑位姿各显示一帧，共 7.4 秒，
左侧按源锚点保持上一原始位姿。这不修改 NPZ 时间戳，也不保留参考 `dt` 或原运动约束；
结果见 [15 FPS 播放报告](../reports/preview_playback_15fps_20260919.json)。
默认“原始 GT 视频”指官方原始位姿的重新渲染。显式 `--official-rgb-npy` 可用同一源 Parquet
episode 根目录的官方 RGB 替换左侧，核验 `uint8 [N,H,W,3]`、源帧数与路径关联，保持宽高比留黑边。
它不恢复真实动作时间；左侧标为官方 RGB，右侧标为 Blender 平滑预览，并明确相机和渲染器不等价。
源图像/相机与新视图不能因放在同一视频中就宣称像素对齐或成为训练观测。
命令、图像命名和运行边界见 [replay/README.md](../replay/README.md)。

## 下一阶段：更流畅的弧线转弯

在宽阔空间，希望直行和转弯之间连续保持速度时，增加独立的空间优化阶段：

1. 从参考路线和膨胀地图提取安全走廊，并保留门口、目标、语义关键路段等锚点。
2. 在走廊内局部优化 `x(t), y(t), yaw(t), v(t), ω(t)`；目标包括偏离原路线、
   加速度/jerk 和曲率变化，约束包括足够间距、动力学和差速运动的非侧滑关系。
3. 对优化曲线进行连续或具有可证明误差界的细分扫掠检查；只检查优化离散节点不够。
4. 失败时保留当前原地转向方案，并明确记录回退原因；不靠放大容忍误差穿过墙角。

不建议把整条路线直接送进无约束 B-spline / Catmull–Rom 再密集采样。
曲线可能切角或超调，也可能改变指令要求的走向。样条可用作优化的参数化形式，
但它本身不提供避障或运动学保证。

## 后续物理回放与训练数据生成链路

```text
官方任务 + 逐步机器人体位姿 + 版本固定的场景资产
  → source：字段、单位、episode 对齐与哈希
  → scene：坐标校准、机器人包络、占据图 / 场景碰撞查询
  → motion：保留路线的时间重定 + 每源运动间隔的稀疏位姿采样
  → validation：全段间距、导数上限、端点 / 指令路径保留
  → replay：按仿真控制周期重新采样连续参考，保存实际位姿、接触、RGB、深度
  → labels：依据实际位姿和显式秒级 horizon 生成 FM / RVQ / apos / opos
  → export：标准 LeRobot、自包含观测、独立 mask、统计与读取验证
```

参考路径与实际回放路径分别保存；发生碰撞、明显跟踪误差或图像缺失时，
该 episode 不能仅凭参考轨迹通过检查而进入正式训练集。
新的相机位姿需要重新渲染。复制邻近 RGB、把原始帧插值后当成真实新观测，
都不能作为几何对齐的训练采集方法。

## 验收指标

每次运行至少记录输入 episode 数、成功数、失败类别、起终点误差、
离原路线最大距离、连续扫掠检查结果、最小间距（实现后）、运动时长和输出帧数，
以及线速度/角速度、加速度和 jerk 最大值。采样检查必须区分每源间隔采样与均匀时间采样，
前者验证源锚点覆盖、每间隔点数、共享端点去重和实际 `timestamp_s`，不能套用固定 dt 检查。
回放后再增加接触次数、碰撞对象、参考与实际位姿误差、RGB/深度有效率和帧对齐误差。

先选窄门、贴墙转弯、连续原地转向、长直行与终点附近等少量代表性路线，
查看地图叠图和第一视角视频，再冻结参数开展批量作业。

  当前代码没有依赖或调用 Nav2，也尚未实现该阶段。
